# Rio（リオ）

Rio はブルーアーカイブの戦術対抗戦（6 人対 6 人の PvP）の画面を横から見て、
対戦の記録を残し、次の対戦の編成を案内するアプリです。
[Aoi](https://github.com/miyabisun/bluearchive-aoi) の姉妹アプリで、ゲームの横に置く小さなウィンドウも、画面の見方も Aoi と同じです。

いまできるのは、次の 4 つです。

- 戦闘履歴の画面を読んでデータベースに登録し、「履歴」タブで見る。
- 戦闘履歴の一覧を読み、どの行をまだ登録していないかをゲームの画面の上に出す。戦闘があったおおよその時刻も付ける。
- 対戦相手を選んだ画面を読み、登録した戦闘から相手の防衛の編成を予測して、「対戦」タブに出す。
- 「編成」の画面で、その防衛に勝った攻撃の編成の生徒を、ゲームの画面の上に印で案内する。

- ゲームは操作しません（クリックやキー入力を送りません）。
  印と文字はゲームの上に重ねた別のウィンドウに描き、クリックはそのままゲームに届きます。
- 読み取った内容はこのパソコンの中だけに保存します。インターネットにつなぐのは、
  「アップデートを確認」で新しいバージョンを探すときと、そのバージョンをダウンロードするときだけです。

## 必要なもの

- Windows 11 と、PC 版ブルーアーカイブ（日本版）
- ゲームのウィンドウの横幅が 1500 ピクセル以上あること

## ダウンロードと起動

1. [最新版のリリースページ](https://github.com/miyabisun/bluearchive-rio/releases/latest) を開きます。
2. ページの下の方にある「Assets」から `bluearchive-rio-x86_64-pc-windows-msvc.exe`
   を押して、ダウンロードします。
3. ダウンロードしたファイルを、デスクトップや「ドキュメント」など好きな場所に置きます。
   インストールの作業はありません。このファイルをダブルクリックすると Rio が起動します。
   - 「Windows によって PC が保護されました」と出たときは、「詳細情報」を押してから
     「実行」を押します。個人が作ったアプリで、電子署名が付いていないために出る表示です。
   - 「Program Files」のような、書き込みに管理者の許可がいる場所には置かないでください。
     そこではアップデートで中身を入れ替えられません。

新しいバージョンが出たときは、Rio の右上の「☰」で設定を開き、「アップデートを確認」を押します。新しいバージョンが
あれば「更新して再起動」のボタンが出るので、押すと入れ替わって起動し直します。

## 使い方

1. ダウンロードしたファイルを起動します。ウィンドウが開きます。ゲームとどちらが先でも構いません。
   ゲームのウィンドウが見つかると、右上の表示が「ゲームを待っています」から「対象外の画面」に変わります。
   Rio が読む画面（戦闘履歴・対戦相手・編成）を開くまでは、この表示のままです。
2. ゲームで「戦術対抗戦」→「対戦履歴」と進みます。一覧の各行の「履歴」ボタンの所に、
   ゲームの画面の上へ「読み取り済み」か「未読」が出ます（下の「戦闘履歴の一覧」）。
3. 「未読」の行の「履歴」を押して、戦闘を開きます。
   題字「戦闘履歴」の右に「読み取り中」と出て、画面が 1 秒ほど止まると、その戦闘が「履歴」タブに登録されて
   「登録しました」に変わります。前に登録した戦闘なら「既に登録済み」と出ます。登録は 1 回だけです。
4. 対戦相手を選ぶと、「対戦」タブに相手の防衛の編成の予測と、おすすめの攻撃が出ます（下の「防衛の編成の予測」）。
   予測と案内は登録した戦闘から作るので、同じ D1 とスペシャルの防衛を登録するまでは出ません。
5. 「攻撃編成」の画面で「編成」を開くと、選ぶ生徒をゲームの画面の上に案内します（下の「編成の案内」）。
6. 終わるときは、ウィンドウを閉じます。

| ウィンドウの部品 | すること |
| --- | --- |
| 「対戦」タブ | 最後に選んだ相手の、防衛の予測（D1〜D4 とスペシャル）とおすすめの攻撃（A1〜A4 とスペシャル） |
| 「履歴」タブ | 登録した戦闘。新しい順に、戦闘があったおおよその時刻（分からない戦闘は登録した日時）、攻撃と防衛のプレイヤー・編成と、勝った側 |
| 右上の表示 | 読み取りの状態。読める画面を開いている間は、その画面の名前。それ以外の画面では「対象外の画面」。戦闘履歴は、登録が済んだかどうかも出す。押すと読み取りを一時中断し、もう一度押すと再開する |
| ☰ | 設定。アップデートの確認、テーマ（自動・ライト・ダーク）、記録の保存先 |

生徒はアイコンで出ます。名前はアイコンにポインタを載せると出ます。
ストライカーを左から、攻撃側は A1〜A4、防衛側は D1〜D4、スペシャルは SP と書きます。

### コマンド

引数を付けて実行すると、ウィンドウを開かずに、コマンドプロンプトや PowerShell に文字で出します。
下の表は、ダウンロードしたファイルの名前を `bluearchive-rio.exe` に変えたときの書き方です。
変えていなければ、`bluearchive-rio` の所にファイルの名前をそのまま書きます。

| コマンド | すること |
| --- | --- |
| `bluearchive-rio read <png>...` | スクリーンショットの戦闘履歴を登録する |
| `bluearchive-rio predict <png>...` | スクリーンショットの対戦相手の、防衛の編成の予測とおすすめの攻撃を表示する |
| `bluearchive-rio list` | 登録した戦闘を新しい順に表示する |
| `bluearchive-rio name <プレイヤー番号> <名前>` | プレイヤーに名前を付ける |
| `bluearchive-rio roster` | Aoi が書き出した手持ちの生徒を表示する |

```text
#1 2026-11-17 03:19:17 攻撃側の勝ち
  攻撃 プレイヤー#1: A1 ホシノ / A2 マリナ / A3 ヒビキ（応援団） / A4 ハスミ（水着） | SP イロハ / SP ミチル（ドレス）
  防衛 プレイヤー#2: D1 アツコ / D2 マリナ / D3 トキ / D4 イオリ | SP イロハ / SP ミチル（ドレス）
```

先頭の日時は Rio がその戦闘を登録した日時で、戦闘があった日時ではありません。

### 戦闘履歴の一覧

「対戦履歴」で開く一覧では、全体が見えている行を読みます。ホイールでスクロールすると、見えた行から順に読みます。

| ゲームの上の文字 | 意味 |
| --- | --- |
| 読み取り済み（行の「履歴」ボタンの左上） | その行の戦闘を登録してある |
| 未読（同じ場所。ボタンをピンクの枠で囲む） | その行の戦闘をまだ登録していない。「履歴」を押して開くと登録する |
| 開き直すと読み取ります（題字の右） | Rio が見る前から開いていた一覧。閉じて開き直すと、行を読み始める |

- 行の「2時間前」から、戦闘があった時刻の範囲（2〜3 時間前）を出します。同じ行を後でまた見ると範囲が狭まります。
  「履歴」タブには、範囲に合わせて「11-18 00:10 ごろ」「11-17 22時ごろ」のように出します。
- 行の「履歴」から開いた戦闘を、その行の戦闘とします。相手・攻守・勝敗のどれも同じ行が続くときは、
  マウスポインタを置いていた行にします（ポインタの位置を見るだけです）。
- ゲームは、一覧を開いたときの「5分前」を出し続けます。Rio が見る前から開いていた一覧では、新しい行を登録しません。
- 上下の端で切れた行は読みません。読めない行には文字を出しません。

### 防衛の編成の予測

「対戦相手」の画面は、相手の防衛のうち先頭のストライカー（D1）とスペシャル 2 人だけを見せ、D2〜D4 を隠します。
Rio は、登録した戦闘の中から D1 とスペシャル 2 人が同じ防衛を探し、その後ろにいた D2〜D4 を予測します。
「対戦」タブでは、予測した生徒を破線の枠のアイコンで出します。`predict` では次のように文字で出します。

```text
対戦相手の防衛: D1 アツコ | SP イロハ / SP ミチル（ドレス）
  この相手の最後の防衛: D2 マリナ / D3 トキ / D4 イオリ
  2回 D2 マリナ / D3 トキ / D4 イオリ (最後に登録 2026-11-17 13:14:04)
  1回 D2 マリナ / D3 イオリ / D4 ハスミ（水着） (最後に登録 2026-11-16 21:00:00)
  おすすめの攻撃 (3戦2勝): A1 ホシノ / A2 マリナ / A3 ミカ / A4 イオリ | SP イロハ / SP ヒマリ
```

- 予測は、同じ名前の相手が最後に登録された防衛の D2〜D4 です（「この相手の最後の防衛」）。
  同じ名前の登録が無ければ、プレイヤーを区別せずに数えて、回数が最も多いものにします。
- 数えるのは防衛の編成だけです。自分が防衛した戦闘も数えます。
- 「おすすめの攻撃」は、予測した防衛（6 人とも同じ）に勝った攻撃のうち、勝った割合が最も高い編成です。
  手持ちにいない生徒を含む編成は出しません。

「対戦相手」の画面では、隠された 3 人の場所に、予測した生徒のアイコンを黄色の枠で重ねます。

### 編成の案内

「編成」の画面では、おすすめの攻撃の 6 人を選べるように、ゲームの画面の上に印を重ねます。
ストライカーの並び順（A1〜A4）は、画面を閉じた後にドラッグで変えます。順番は「対戦」タブの「おすすめの攻撃」に出ます。

| 印 | 意味 |
| --- | --- |
| 黄色の枠のアイコン（「？」の上） | 予測した相手の D2〜D4 |
| ピンクの枠（一覧のカード） | 選ぶ生徒 |
| ピンクの枠の中のアイコンと三角形（一覧の右下か右上） | 選ぶ生徒が一覧の見えていない所にいる。三角形の向きへスクロールする |
| 赤い枠と暗い幕（下の行のカード） | 編成から外す生徒 |
| ピンクの枠（「STRIKER」か「SPECIAL」のタブ） | 開いているタブの生徒は選び終えた。もう一方のタブを開く |

- スクロールの向きは、一覧が「Lv」の降順で並んでいる前提で、Aoi が読んだ Lv・星・絆ランクから決めます。
  決められないときは、三角形を上下の両方に出します。
- ゲームのウィンドウが手前に無いときと、予測もおすすめの攻撃も無いときは、印を出しません。

### プレイヤーの名前

Rio はプレイヤーの名前を文字としては読みません。画面に描かれた名前の形でプレイヤーを見分け、
同じ形なら同じプレイヤーとして番号を付けます。「履歴」タブには、ゲームが描いた名前をそのまま絵で出します。
文字の名前にしたいときは、`bluearchive-rio name 2 ライバル` のように自分で付けます。

名前の左のアイコンが「？」のプレイヤーは匿名です。匿名のプレイヤーには番号を付けず、「匿名」と表示します。
匿名の 2 人が同じ人かどうかは分からないので、1 人にまとめません。
自分で「匿名」という名前を付けたプレイヤーはアイコンが「？」ではないので、ほかのプレイヤーと同じく番号が付きます。

### 手持ちの生徒

手持ちの生徒は Aoi が読んだものを使います。Aoi が `ドキュメント\Aoi\aoi.yaml` に書き出す内容を
Rio が読むので、Rio で生徒を読み直す必要はありません。

## 登録されるデータ

データベースは SQLite で、`%APPDATA%\io.github.miyabisun.bluearchive-rio\rio.db` にあります。
環境変数 `RIO_DATA_DIR` にフォルダを指定すると、そこに作ります。
同じフォルダの `settings.json` に、テーマとウィンドウの位置を覚えます。

- `battles`: 1 行が 1 戦闘です。`seen_at`（登録した日時）、`attacker`・`defender`（プレイヤー番号。匿名なら空）、
  `attacker_won`（攻撃側が勝ったら 1）、生徒の列 `a1`〜`a4`・`asp1`・`asp2`・`d1`〜`d4`・`dsp1`・`dsp2`
  （SchaleDB の生徒 ID）と、`fingerprint`（戦闘の指紋）を持ちます。
  スペシャルの 2 人は左右を区別せず、ID の小さい方を `asp1`・`dsp1` に入れます。
- `players`: プレイヤー番号 `id`、画面に描かれた名前の画像 `plate`、付けた名前 `name` を持ちます。
- `listed`: 1 行が戦闘履歴の一覧の 1 行です。`attacked`（自分が攻撃なら 1）、`won`（自分が勝ったら 1）、
  `opponent`（相手のプレイヤー番号。匿名なら空）、`earliest`・`latest`（戦闘があった時刻の範囲。1970 年からの秒）、
  `place`（一覧での並び。大きいほど新しい）、`battle`（その行から開いて登録した戦闘の `id`。まだなら空）を持ちます。

ゲームは戦闘の日時を「20時間前」のようにしか表示せず、同じ相手との戦闘が続けて並ぶこともあります。
そこで Rio は、12 人のダメージを `a1` から `dsp2` の順に `-` でつないだ文字列を戦闘の指紋とし、
指紋が同じなら同じ戦闘として扱います。
ダメージは勝敗をほとんど表さないので（回復や被弾は数えず、召喚物や回復した相手を攻撃すると増えます）、
指紋のほかには使いません。

SQLite を読める道具（`sqlite3` コマンドなど）で、自分で引き出せます。
たとえば、プレイヤー 2 番が防衛したときの編成は次のように出します。

```sh
sqlite3 "%APPDATA%\io.github.miyabisun.bluearchive-rio\rio.db" "SELECT seen_at, attacker_won, d1, d2, d3, d4, dsp1, dsp2 FROM battles WHERE defender = 2"
```

## 読めないとき

Rio は、戦闘履歴のどこか 1 か所でも確実に読めなければ、その戦闘を登録しません。間違った記録を残さないためです。
読めない間、右上の表示は「戦闘履歴を読み取り中」のまま変わりません。

- ウィンドウの横幅が 1500 ピクセルより狭いと読みません。
- 幅によっては数字を読み切れないことがあります。ウィンドウの大きさを少し変えると読めます。
- 実装されたばかりの生徒は、Rio が持つ生徒の一覧にまだいません。下の「生徒の一覧の更新」で取り込みます。
- 生徒が 6 人そろっていない編成は、まだ読めません。
- 戦闘履歴の一覧で読めない行は、上の「戦闘履歴の一覧」にあります。
- 「編成」の画面のうち、「SPECIAL」のタブを開いた状態と、編成に空きがある状態は、まだ実際の画面で確かめていません。

## 開発

[Rust](https://www.rust-lang.org/ja/tools/install) を入れて `cargo build --release` を実行すると、
`target\release\bluearchive-rio.exe` ができます。検査は次の 3 つです。

```sh
cargo fmt --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked
```

ウィンドウは [GPUI](https://www.gpui.rs/) で描きます。画面の規則は [DESIGN.md](DESIGN.md) にあります。

main へ push する前に同じ検査を走らせるには、クローンごとに 1 回 `git config core.hooksPath .githooks` を実行します。
配布する実行ファイルは、バージョンのタグが付いたコミットから GitHub Actions（`.github/workflows/release.yml`）が作ります。

読み取りのテストは、ゲームの画面の画像を `tests/fixtures` から読みます。
対象は `tests` の `history.rs`・`list.rs`・`opponent.rs`・`formation.rs` です。
画面にはプレイヤーの名前が写るので、この画像はリポジトリに含めていません。画像が無いと、読み取りのテストは失敗します。

- 生徒の一覧の更新: `powershell -File tools/schaledb/update.ps1` を実行します。
  [SchaleDB](https://schaledb.com/) から日本版の生徒の一覧とアイコンを `data/schaledb` に取り込みます。
- 読み取りの手本の作り直し: `cargo run --example make_refs` を実行します。
  `tests/fixtures` の画面から、読み取りの手本を `data/` に切り出します。
  手本は、3 つの画面の題字・攻撃と防衛の絵・ダメージの数字・匿名の「？」の絵・一覧の時刻の文字です。
  [Noto Sans JP](https://github.com/notofonts/noto-cjk/tree/main/Sans/SubsetOTF/JP) の `NotoSansJP-Bold.otf` を置いたフォルダを
  引数に付けると、ゲームの上に出す文字の絵（`data/words`）も描き直します。
