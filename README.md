# Rio（リオ）

Rio はブルーアーカイブの戦術対抗戦（6 人対 6 人の PvP）の画面を横から見て、
対戦の記録を残し、次の対戦の編成を案内するアプリです。
[Aoi](https://github.com/miyabisun/bluearchive-aoi) の姉妹アプリで、ゲームの横に置く小さなウィンドウも、画面の見方も Aoi と同じです。

いまできるのは、次の 6 つです。

- 戦闘履歴の画面を読んでデータベースに登録し、「履歴」タブで見る。
- 戦闘履歴の一覧を読み、どの行をまだ登録していないかをゲームの画面の上に出す。戦闘があったおおよその時刻も付ける。
- 対戦相手を選んだ画面を読み、登録した戦闘から相手の防衛の編成の候補と、それに勝った攻撃の候補を「対戦」タブに出す。
  お迎えしていない生徒や、自分で「編成NG」にした生徒を含む攻撃は、選べない行として下に分ける。
- 「編成」の画面で、候補から選んだ攻撃の編成の生徒を、ゲームの画面の上に印で案内する。
- SNS や動画が紹介する「この防衛にはこの攻め」を、「編成登録」タブに自分の手で登録する。紹介された戦績と元のページも付けられる。
  登録した編成も「対戦」タブの候補に出す。よく使う生徒は「Tier表」で S〜D に分けておくと、選ぶ一覧の先頭に並ぶ。
- AI のエージェントから、MCP で編成を登録・編集・削除する（下の「MCP で登録する」）。

- ゲームは操作しません（クリックやキー入力を送りません）。
  印と文字はゲームの上に重ねた別のウィンドウに描き、クリックはそのままゲームに届きます。
- 読み取った内容はこのパソコンの中だけに保存します。インターネットにつなぐのは、
  「アップデートを確認」で新しいバージョンを探すときと、そのバージョンをダウンロードするときだけです。

## 必要なもの

- Windows 11 と、PC 版ブルーアーカイブ（日本版）
- ゲームのウィンドウの横幅が 1500 ピクセル以上あること

## ダウンロードと起動

1. [最新版のリリースページ](https://github.com/miyabisun/bluearchive-rio/releases/latest) を開きます。
2. ページの下の方にある「Assets」から `bluearchive-rio-x86_64-pc-windows-msvc.exe`
   を押して、ダウンロードします。
3. ダウンロードしたファイルを、デスクトップや「ドキュメント」など好きな場所に置きます。
   インストールの作業はありません。このファイルをダブルクリックすると Rio が起動します。
   - 「Windows によって PC が保護されました」と出たときは、「詳細情報」を押してから
     「実行」を押します。個人が作ったアプリで、電子署名が付いていないために出る表示です。
   - 「Program Files」のような、書き込みに管理者の許可がいる場所には置かないでください。
     そこではアップデートで中身を入れ替えられません。

新しいバージョンが出たときは、Rio の右上の「☰」で設定を開き、「アップデートを確認」を押します。新しいバージョンが
あれば「更新して再起動」のボタンが出るので、押すと入れ替わって起動し直します。

## 使い方

1. ダウンロードしたファイルを起動します。ウィンドウが開きます。ゲームとどちらが先でも構いません。
   ゲームのウィンドウが見つかると、右上の表示が「ゲームを待っています」から「対象外の画面」に変わります。
   Rio が読む画面（戦闘履歴・対戦相手・編成）を開くまでは、この表示のままです。
2. ゲームで「戦術対抗戦」→「対戦履歴」と進みます。一覧の各行の「履歴」ボタンの所に、
   ゲームの画面の上へ「読み取り済み」か「未読」が出ます（下の「戦闘履歴の一覧」）。
3. 「未読」の行の「履歴」を押して、戦闘を開きます。
   題字「戦闘履歴」の右に「読み取り中」と出て、画面が 1 秒ほど止まると、その戦闘が「履歴」タブに登録されて
   「登録しました」に変わります。前に登録した戦闘なら「既に登録済み」と出ます。登録は 1 回だけです。
4. 対戦相手を選ぶと、「対戦」タブに相手の防衛の編成の候補と、それぞれに勝った攻撃の候補が出ます（下の「防衛と攻撃の候補」）。
   使う攻撃の行をクリックして選びます。候補は登録した戦闘から作るので、同じ D1 とスペシャルの防衛を登録するまでは出ません。
5. 「攻撃編成」の画面で「編成」を開くと、選んだ攻撃の生徒をゲームの画面の上に案内します（下の「編成の案内」）。
6. 終わるときは、ウィンドウを閉じます。

| ウィンドウの部品 | すること |
| --- | --- |
| 「対戦」タブ | 最後に選んだ相手の、防衛の候補（6 人の編成。有り得そうな順に 5 つまで）と、それぞれに勝った攻撃の候補（A1〜A4 とスペシャル）。クリックで選ぶ |
| 「履歴」タブ | 登録した戦闘。新しい順に、戦闘があったおおよその時刻（分からない戦闘は登録した日時）、攻撃と防衛のプレイヤー・編成と、勝った側 |
| 「編成登録」タブ | 紹介された攻めと防衛の組を登録する。1 行目の「追加」「編集」「Tier表」で画面を切り替える（下の「編成を手で登録する」） |
| 右上の表示 | 読み取りの状態。読める画面を開いている間は、その画面の名前。それ以外の画面では「対象外の画面」。戦闘履歴は、登録が済んだかどうかも出す。押すと読み取りを一時中断し、もう一度押すと再開する |
| ☰ | 設定。アップデートの確認、テーマ（自動・ライト・ダーク）、記録の保存先 |

生徒はアイコンで出ます。名前はアイコンにポインタを載せると出ます。
ストライカーを左から、攻撃側は A1〜A4、防衛側は D1〜D4、スペシャルは SP と書きます。

### コマンド

引数を付けて実行すると、ウィンドウを開かずに、コマンドプロンプトや PowerShell に文字で出します。
下の表は、ダウンロードしたファイルの名前を `bluearchive-rio.exe` に変えたときの書き方です。
変えていなければ、`bluearchive-rio` の所にファイルの名前をそのまま書きます。

| コマンド | すること |
| --- | --- |
| `bluearchive-rio read <png>...` | スクリーンショットの戦闘履歴を登録する |
| `bluearchive-rio predict <png>...` | スクリーンショットの対戦相手の、防衛の編成の候補と、それぞれに勝った攻撃の候補を表示する |
| `bluearchive-rio list` | 登録した戦闘を新しい順に表示する |
| `bluearchive-rio name <プレイヤー番号> <名前>` | プレイヤーに名前を付ける |
| `bluearchive-rio roster` | Aoi が書き出した手持ちの生徒を表示する |
| `bluearchive-rio mcp` | MCP サーバーとして動く（下の「MCP で登録する」） |

```text
#1 2026-11-17 03:19:17 攻撃側の勝ち
  攻撃 プレイヤー#1: A1 ホシノ / A2 マリナ / A3 ヒビキ（応援団） / A4 ハスミ（水着） | SP イロハ / SP ミチル（ドレス）
  防衛 プレイヤー#2: D1 アツコ / D2 マリナ / D3 トキ / D4 イオリ | SP イロハ / SP ミチル（ドレス）
```

先頭の日時は Rio がその戦闘を登録した日時で、戦闘があった日時ではありません。

### 戦闘履歴の一覧

「対戦履歴」で開く一覧では、全体が見えている行を読みます。ホイールでスクロールすると、見えた行から順に読みます。

| ゲームの上の文字 | 意味 |
| --- | --- |
| 読み取り済み（行の「履歴」ボタンの左上） | その行の戦闘を登録してある |
| 未読（同じ場所。ボタンをピンクの枠で囲む） | その行の戦闘をまだ登録していない。「履歴」を押して開くと登録する |
| 開き直すと読み取ります（題字の右） | Rio が見る前から開いていた一覧。閉じて開き直すと、行を読み始める |

- 行の「2時間前」から、戦闘があった時刻の範囲（2〜3 時間前）を出します。同じ行を後でまた見ると範囲が狭まります。
  「履歴」タブには、範囲に合わせて「11-18 00:10 ごろ」「11-17 22時ごろ」のように出します。
- 行の「履歴」から開いた戦闘を、その行の戦闘とします。押した行は、ゲームが押した所に描く白い輪で見分けます。
  マウスとタッチのどちらで押しても輪は出ます。輪が見えなかったときは、開いた戦闘と相手・攻守・勝敗の同じ行にします。
  端で切れた行も、「履歴」ボタンが見えていて、前に全体を見た行なら扱います。
- 「未読」は、その行から戦闘を開いたことがまだ無い、という意味です。
  v0.1.4 より前に登録した戦闘の行は、一度開くと「読み取り済み」に変わります（開くと「既に登録済み」と出ます）。
- 行は、隣り合って見えた行のつながりで見分けます。飛ばして見た所は、間をスクロールするとつながります。
- ゲームは、一覧を開いたときの「5分前」を出し続けます。Rio が見る前から開いていた一覧では、新しい行を登録しません。
- 上下の端で切れた行は読みません。読めない行と、どの行か決められない行には文字を出しません。

### 防衛と攻撃の候補

「対戦相手」の画面は、相手の防衛のうち先頭のストライカー（D1）とスペシャル 2 人だけを見せ、D2〜D4 を隠します。
Rio は、登録した戦闘の中から D1 とスペシャル 2 人が同じ防衛を探し、その後ろにいた D2〜D4 を候補として並べます。
どの候補が当たりかと、どの攻撃を使うかは、Rio が決めずに、自分で選びます。

「対戦」タブの「防衛の候補」に、有り得そうな順に 5 つまで出ます。候補のすぐ下に、その防衛に勝った攻撃が並びます。
候補の行には、防衛の 6 人を全員出します。ゲームが見せている D1 とスペシャルはそのまま出し、Rio が記録から補った D2〜D4 は青い枠で囲みます。

| クリックする所 | 選ばれるもの |
| --- | --- |
| 攻撃の行 | その攻撃と、その攻撃が勝った防衛の候補。「編成」の画面で、この攻撃の生徒を案内する |
| 防衛の候補の行 | 防衛の候補だけ。隠された D2〜D4 の場所に、この 3 人を出す |

選んだ行の前には ✓ が付きます。もう一度クリックすると外れます。相手が変わると、何も選んでいない状態に戻ります。

候補は、流行（いま使われている編成）の順に並びます。見出しと、行の右に出る根拠は次のとおりです。

| 順番 | 見出し | 根拠の表示 | 意味 |
| --- | --- | --- | --- |
| 1 | 本人が使った編成（過去1か月） | 本人 11-17 | 同じ名前の相手が、過去 30 日にこの防衛を使った。最後に使った日の新しい順 |
| 2 | 登録した編成 | 登録 | 「編成登録」タブで登録した防衛。戦闘の記録が無くても出る。記録にもあれば、使った人数の多い順 |
| 3 | 流行（過去2週間） | ほか 3人 | 過去 14 日に、ほかのプレイヤーがこの防衛を使った。使った人数の多い順（同じなら新しい順） |
| 4 | それより前の記録 | ほか 2人（2週間より前） | 上の期間より前の戦闘にしか無い編成。新しい順 |
| 5 | 自分の防衛だけにある編成 | 自分の防衛 | 自分の防衛にしか無い編成。新しい順 |

- 数えるのは人数だけです。同じ相手と何度戦っても 1 人です。
  名前が隠れた相手は見分けられないので、同じ編成ならまとめて 1 人と数えます。
- 自分は人数に入れません。防衛の記録は自分のものが最も多くたまるためです。
- 戦闘の日は、戦闘履歴の一覧の行（「3日前」など）から分かるものを使います。分からない戦闘は、登録した日を使います。
- 攻撃の候補は、その防衛（6 人とも同じ）に 1 回以上勝った編成を 5 つまでと、「編成登録」タブで登録した攻撃のすべてです。
  並べ方は、下の「攻撃の候補の順番」にあります。
  出せない生徒を含む編成は選べない行にして、その下に同じ決まりで出します（下の「出せない生徒と編成NG」）。
- 自分がどのプレイヤーかは、戦闘履歴の画面の自分の側から記録します。
  v0.1.10 までに登録した戦闘には記録が無いので、最も多くの戦闘に出てくるプレイヤーを自分とみなします。

#### 攻撃の候補の順番

攻撃の候補は、推定の勝率の高い順に並びます。
紹介された戦績は話半分として、1 戦を半分の重みで数えます。実際に攻めで使うまで、本当の勝率は分からないためです。

```text
推定の勝率 = (自分の勝ち + 紹介の勝ち ÷ 2) ÷ (自分の戦数 + 紹介の戦数 ÷ 2)
```

| 行の右の表示 | 意味 |
| --- | --- |
| 3戦2勝 | 自分がその攻撃で戦った記録 |
| 紹介 20戦18勝 | 登録した攻撃の、紹介された戦績 |
| 登録 | 登録した攻撃で、紹介された戦績が無いもの |

- 自分で戦うほど、自分の戦績が効きます。「紹介 20戦18勝」の攻撃で 4 戦 0 勝なら、推定の勝率は 9 ÷ 14 で約 64% です。
- 推定の勝率が同じなら、戦数（紹介は半分に数える）の多い方が先です。それも同じなら、新しい方が先です。
- 自分の戦績も紹介の戦績も無い登録は、勝率が分からないので、勝率のある候補の後ろに出します。
- 登録した攻撃は 5 つまでの数に入れず、必ず出します。

`predict` では次のように文字で出します。

```text
対戦相手の防衛: D1 アツコ | SP イロハ / SP ミチル（ドレス）
  1. D2 マリナ / D3 トキ / D4 イオリ （本人 11-17）
     3戦2勝 A1 ホシノ / A2 マリナ / A3 ミカ / A4 イオリ | SP イロハ / SP ヒマリ
     紹介 20戦18勝 A1 イオリ / A2 マリナ / A3 ミカ / A4 ホシノ | SP イロハ / SP ヒマリ
     除外 1戦1勝 A1 ホシノ / A2 マリナ / A3 トキ / A4 イオリ | SP イロハ / SP ヒマリ
       トキ: 編成NG（右クリックで外せます）
  2. D2 マリナ / D3 イオリ / D4 ハスミ（水着） （ほか 2人）
     勝った攻撃は、まだ登録がありません
```

「対戦相手」の画面では、防衛の候補を選ぶと、隠された 3 人の場所にその生徒のアイコンを黄色の枠で重ねます。

### 出せない生徒と編成NG

記録にある攻撃には、自分では出せない生徒が入っていることがあります。次の生徒を含む攻撃は、
使える攻撃の下に灰色で並び、クリックしても選べません。

| 出せない生徒 | 決まり方 | 使えるようにするには |
| --- | --- | --- |
| お迎えしていない生徒 | Aoi が読んだ手持ちの生徒にいない（Aoi の読み取り結果が無いときは、この理由では除外しない） | お迎えして、Aoi で生徒を読み直す |
| 編成NG の生徒 | 自分で編成NG にした（育てていなくて実戦に出せない生徒など） | 編成NG を外す |

灰色の行の中で、出せない生徒のアイコンは赤い枠で囲み、赤い斜めの線を重ねます。
そのアイコンにポインタを載せると、生徒の名前の下に理由が出ます。

| すること | 操作 |
| --- | --- |
| 編成NG にする | 「対戦」タブの攻撃の候補で、生徒のアイコンを右クリックして「編成NG」を選ぶ。または「Tier表」で、生徒を NG の行へドラッグする |
| 編成NG を外す | 赤い枠のアイコンを右クリックして「編成NGを外す」を選ぶ。または「Tier表」で、NG の行の生徒を下の一覧へドラッグする |

編成NG が変えるのは、この攻撃の候補だけです。編成NG は「自分では出せない」という印で、ほかでは普通の生徒と同じに扱います。

| 場所 | 編成NG の生徒 |
| --- | --- |
| 攻撃の候補（「対戦」タブ） | その生徒を含む攻撃を、選べない行にする |
| 防衛の候補（「対戦」タブ） | 変わらない。相手の防衛として出て、選べる |
| 「追加」の一覧と枠 | 変わらない。攻めにも防衛にも入れて登録できる |
| Tier | 変わらない。Tier を付けたまま編成NG にできる |

編成NG にした生徒が、選んでいた攻撃に入っていたら、その攻撃の選択は外れます（防衛の候補の選択は残ります）。
編成NG は次に起動したときも残ります。編成NG の生徒の一覧は、「編成登録」タブの「Tier表」の NG の行です（下の「生徒を Tier と NG に分ける」）。

### 編成を手で登録する

X（Twitter）や YouTube で「この防衛にはこの攻めが有利」と紹介された編成を、自分で戦う前に登録しておけます。
「編成登録」タブの 1 行目で、3 つの画面を切り替えます。

| 画面 | すること |
| --- | --- |
| 追加 | 攻めと防衛の 6 人ずつを入れて登録する |
| 編集 | 登録した編成を見て、変える・消す |
| Tier表 | よく使う生徒を Tier に、出せない生徒を NG に分ける（下の「生徒を Tier と NG に分ける」） |

「追加」では、上の行に攻め、下の行に防衛の 6 人ずつを入れて、「編成登録」を押します。

| すること | 操作 |
| --- | --- |
| 入れる枠を選ぶ | 枠をクリックする。選んだ枠は、4 隅に黄色のかぎ形が付く。開いたときは攻めの左端 |
| 生徒を入れる | 下の一覧の生徒をクリックする。選んだ枠に入り、選択が右隣の枠へ移る（攻めの右端の次は防衛の左端、防衛の右端の次は攻めの左端） |
| 好きな枠へ入れる | 一覧の生徒を、枠へドラッグ＆ドロップする |
| 枠の中身を入れ替える | 枠から枠へドラッグする |
| 生徒を探す | 入力欄に名前をひらがなかカタカナで打つ。右のボタンで、クラス・攻撃タイプ・防御タイプで絞る |
| 紹介された戦績を付ける | 「紹介」の右の 2 つの欄に、戦数と勝数を入れる。初めは 1 戦 1 勝。数字を打つか、欄を選んで ↑↓ のキーで 1 ずつ変える。勝数の欄の ↑ で勝数が戦数を超えるときは、戦数も 1 増える（3 戦 3 勝 → 4 戦 4 勝）。付けないときは両方を空にする |
| 元のページを付ける | その右の欄に、紹介していたページの URL を入れる。`http://` か `https://` で始まるものに限る |
| コピーした文字を貼り付ける | 欄を選んで Ctrl+V を押す。または欄を右クリックして「貼り付け」を選ぶ |
| 登録する | 12 枠がすべて埋まると「編成登録」を押せる。枠の中身は残るので、同じ防衛への別の攻めを続けて登録できる。戦績は 1 戦 1 勝に、URL は空に戻る |

- 戦績の欄に入るのは数字だけです。戦数と勝数の片方だけのときと、勝数が戦数より多いときは、「編成登録」を押せません。
  押せないボタンにポインタを載せると、足りないものが出ます。
- 絞り込みのボタンは、押すと押し込まれたままになり、もう一度押すと戻ります。
  同じ種類のボタン（クラスどうしなど）は 1 つだけ押せます。別のボタンを押すと、前のボタンは戻ります。種類が違うボタンは、すべてに当てはまる生徒だけを出します。
- 一覧は Tier の高い順（S から D、その後は Tier の無い生徒）で、同じ Tier の中は名前の順です。
  編成NG の生徒も、ほかの生徒と同じ場所に同じ枠で並びます。紹介された編成や相手の防衛には、自分では出せない生徒も入るためです。
- 枠の色は Tier の色で、背景は左上が攻撃タイプ、右下が防御タイプの色です。
  生徒の名前・属性・Tier は、アイコンにポインタを載せると出ます。
- 一覧には、選んだ枠に入れられる生徒だけが出ます。ストライカーの枠を選んでいる間はストライカー、スペシャルの枠ならスペシャルです。
  ドラッグでも、役割の違う枠には入りません。同じ生徒を同じ行にもう一度入れると、前の枠から移ります。
- 登録した編成は、対戦相手の D1 とスペシャルが登録した防衛と同じときに、「対戦」タブの「登録した編成」に出ます（上の「防衛と攻撃の候補」）。

「編集」には、登録した編成が新しい順に並びます。行には、攻めと防衛の 6 人ずつ、紹介された戦績、元のページの URL が出ます。

| すること | 操作 |
| --- | --- |
| 登録を変える | 行の「編集」を押す。「追加」の枠と欄にその登録が入るので、直して「変更を保存」を押す。やめるときは「やめる」を押す |
| 登録を消す | 行の「削除」を押す。または「対戦」タブで、その攻撃の行の戦績を右クリックして「登録を消す」を選ぶ |
| 消した登録を戻す | 消した直後に、ウィンドウの下に出る「元に戻す」を押す。この表示は 8 秒で消える |
| 元のページを開く | 行の URL を押す。ブラウザで開く |

- 「編集」を押す前に「追加」で入れていた枠と欄の中身は、保存するかやめると元に戻ります。
- 同じ攻めと防衛の組は 1 つだけ登録できます。ほかの登録と同じ組になっているあいだは、「変更を保存」を押せません。

### 生徒を Tier と NG に分ける

「編成登録」タブの「Tier表」で、よく使う生徒を S・A・B・C・D の 5 つの Tier に分けておけます。
Tier のある生徒は、「追加」の一覧で Tier の高い順に先頭へ並び、枠が Tier の色になります。
D の下の NG の行には、編成NG の生徒が並びます（上の「出せない生徒と編成NG」）。
Tier と編成NG は別々に付きます。Tier S で編成NG の生徒は、S の行と NG の行の両方に並びます。

| 行 | S | A | B | C | D | NG |
| --- | --- | --- | --- | --- | --- | --- |
| 色 | 紫 | 黄 | 青 | 緑 | 灰 | 赤 |

上は表の 6 行、下はどの行にも入れていない生徒の一覧です。操作はすべてドラッグです。クリックでは何も起きません。

| すること | 操作 |
| --- | --- |
| 行に入れる | 一覧の生徒を、行へドラッグ＆ドロップする。入れた生徒は一覧から消える |
| 別の Tier へ移す | Tier の行の生徒を、別の Tier の行へドラッグする |
| Tier のある生徒を編成NG にする | Tier の行の生徒を、NG の行へドラッグする。Tier は残り、両方の行に並ぶ |
| 編成NG の生徒に Tier を付ける | NG の行の生徒を、Tier の行へドラッグする。編成NG は残り、両方の行に並ぶ |
| 行から外す | 行の生徒を、下の一覧へドラッグする。外れるのは、ドラッグを始めた行だけ |
| 生徒を探す | 入力欄に名前を打つ。右のボタンで絞る。赤の「ST」はストライカー、青の「SP」はスペシャル |

- Tier は 1 人に 1 つです。編成NG は、Tier があっても無くても付けられます。
- もう入っている行へは落とせません（落としても何も変わらないため）。
- 行の生徒にポインタを載せると、名前の下に Tier と編成NG が出ます。
- 行の中は、ストライカー、スペシャルの順に並びます。それぞれの中は名前の順です。
- 枠の色は、ストライカーが赤、スペシャルが青です。下の一覧は名前の順に並びます。
- 検索と絞り込みは「追加」とは別に持ちます。片方で絞っても、もう片方の一覧は変わりません。

### MCP で登録する

AI のエージェント（MCP のクライアント）から、編成の登録・編集・削除ができます。
クライアントに、Rio を MCP サーバーとして登録します。通信は標準入出力（stdio）です。

| 項目 | 値 |
| --- | --- |
| コマンド | ダウンロードしたファイルの場所（例: `C:\Tools\bluearchive-rio.exe`） |
| 引数 | `mcp` |

設定を JSON で書くクライアントでは、次のように書きます。

```json
{
  "mcpServers": {
    "rio": { "command": "C:\\Tools\\bluearchive-rio.exe", "args": ["mcp"] }
  }
}
```

| ツール | すること |
| --- | --- |
| `find_students` | 生徒を名前の一部で探す（ひらがなでもよい） |
| `list_formations` | 登録した編成を、新しい順にすべて返す |
| `register_formation` | 攻め（`attack`）と防衛（`defense`）の 6 人ずつを登録する。戦績（`battles`・`wins`）と `url` も付けられる |
| `edit_formation` | `id` の登録を変える。指定した項目だけが変わる。戦績と `url` は `null` で消せる |
| `delete_formation` | `id` の登録を消す |

- 生徒は、名前（`"ホシノ（水着）"`）か SchaleDB の ID（`10045`）で指定します。
  同じ名前の生徒が 2 人いるときは登録せず、候補を ID 付きで返します。
- 6 人は、ストライカー 4 人、スペシャル 2 人の順に並べます。役割の違う枠に入れた生徒と、同じ生徒の重複は断ります。
- MCP サーバーはウィンドウを開きません。ウィンドウのアプリと同じデータベースを読み書きし、同時に動かせます。
- MCP での変更がウィンドウに出るのは、「編集」を開き直したときと、次に対戦相手を読んだときです。

### 編成の案内

「編成」の画面では、「対戦」タブで選んだ攻撃の 6 人を選べるように、ゲームの画面の上に印を重ねます。
選ぶ生徒の印は、1 人ずつ出します。ゲームは選んだ生徒を左の空き枠から入れるので、いちばん左の空き枠に入る生徒を先に示します。
印の順に選ぶと、空き枠は攻撃の並び順（A1〜A4）のとおりに埋まります。順番は「対戦」タブの選んだ行に出ます。
先に入っていた生徒の位置が違うときは、画面を閉じた後にドラッグで変えます。

| 印 | 意味 |
| --- | --- |
| 黄色の枠のアイコン（「？」の上） | 選んだ防衛の候補の D2〜D4 |
| ピンクの枠（一覧のカード） | 次に選ぶ生徒 |
| ピンクの枠の中のアイコンと三角形（一覧の右下か右上） | 次に選ぶ生徒が一覧の見えていない所にいる。三角形の向きへスクロールする。アイコンに重なる「2列」は、あと何列先にいるか |
| 赤い枠と暗い幕（下の行のカード） | 編成から外す生徒 |
| ピンクの枠（「STRIKER」か「SPECIAL」のタブ） | 開いているタブの生徒は選び終えた。もう一方のタブを開く |

- スクロールの向きは、一覧が「Lv」の降順で並んでいる前提で決めます。
  Lv・星・絆ランク（Aoi が読んだ値）の高い順、同じなら学校の順、名前の順です。
  決められないときは、三角形を上下の両方に出します。
- 「◯列」は、見えている端の列の隣を 1 列目として数えます。Aoi が Lv・星・絆ランクを読めていない生徒が手持ちにいるときと、見えているカードが並びの計算と合わないときは、数を出しません。
  一覧に、Aoi で一度も読んでいない生徒がいると、数はずれることがあります。
- ゲームのウィンドウが手前に無いときと、候補を選んでいないときは、印を出しません。

### プレイヤーの名前

Rio はプレイヤーの名前を文字としては読みません。画面に描かれた名前の形でプレイヤーを見分け、
同じ形なら同じプレイヤーとして番号を付けます。「履歴」タブには、ゲームが描いた名前をそのまま絵で出します。
文字の名前にしたいときは、`bluearchive-rio name 2 ライバル` のように自分で付けます。

名前の左のアイコンが「？」のプレイヤーは匿名です。匿名のプレイヤーには番号を付けず、「匿名」と表示します。
匿名の 2 人が同じ人かどうかは分からないので、1 人にまとめません。
自分で「匿名」という名前を付けたプレイヤーはアイコンが「？」ではないので、ほかのプレイヤーと同じく番号が付きます。

### 手持ちの生徒

手持ちの生徒は Aoi が読んだものを使います。Aoi が `ドキュメント\Aoi\aoi.yaml` に書き出す内容を
Rio が読むので、Rio で生徒を読み直す必要はありません。

## 登録されるデータ

データベースは SQLite で、`%APPDATA%\io.github.miyabisun.bluearchive-rio\rio.db` にあります。
環境変数 `RIO_DATA_DIR` にフォルダを指定すると、そこに作ります。
同じフォルダの `settings.json` に、テーマとウィンドウの位置を覚えます。
`list-trail.log` には、一覧の行をどう見分けたかと、開いた戦闘をどの行のものにしたかを書きます。
行・戦闘・プレイヤーの番号だけで、名前は書きません。不具合を調べるためのもので、512KB を超えると作り直します。

- `battles`: 1 行が 1 戦闘です。`seen_at`（登録した日時）、`attacker`・`defender`（プレイヤー番号。匿名なら空）、
  `attacker_won`（攻撃側が勝ったら 1）、生徒の列 `a1`〜`a4`・`asp1`・`asp2`・`d1`〜`d4`・`dsp1`・`dsp2`
  （SchaleDB の生徒 ID）と、`fingerprint`（戦闘の指紋）、`user_attacked`（自分が攻撃した戦闘なら 1。v0.1.10 までに登録した戦闘は空）を持ちます。
  スペシャルの 2 人は左右を区別せず、ID の小さい方を `asp1`・`dsp1` に入れます。
- `players`: プレイヤー番号 `id`、画面に描かれた名前の画像 `plate`、付けた名前 `name` を持ちます。
- `list_rows`: 1 行が戦闘履歴の一覧の 1 行です。`attacked`（自分が攻撃なら 1）、`won`（自分が勝ったら 1）、
  `opponent`（相手のプレイヤー番号。匿名なら空）、`earliest`・`latest`（戦闘があった時刻の範囲。1970 年からの秒）、
  `above`（一覧ですぐ上に見えた行の `id`。まだ見ていなければ空）、
  `battle`（その行から開いて登録した戦闘の `id`。まだなら空）を持ちます。
  v0.1.7 までの `listed` 表は、戦闘を開いた行だけをこの表へ移して消します。
  v0.1.9 までに覚えた行は、戦闘を開いた行だけを残して、行のつながりを一度作り直します。
- `barred`: 編成NG にした生徒です。1 行が 1 人で、`student`（SchaleDB の生徒 ID）を持ちます。
- `tiers`: 「Tier表」で Tier に入れた生徒です。1 行が 1 人で、`student`（SchaleDB の生徒 ID）と、
  `tier`（S が 0、A が 1、B が 2、C が 3、D が 4）を持ちます。同じ生徒が `barred` にもいてかまいません。
  v0.1.17 だけは、編成NG を `tier` が 5 の行として持ち、編成NG にした生徒の Tier を消していました。
  その行は `barred` 表へ移します。v0.1.17 で消えた Tier は戻らないので、「Tier表」で付け直してください。
- `registered`: 「編成登録」タブで登録した編成です。1 行が攻めと防衛の 1 組で、`added_at`（登録した日時）と、
  `battles` と同じ生徒の列 `a1`〜`a4`・`asp1`・`asp2`・`d1`〜`d4`・`dsp1`・`dsp2` を持ちます。
  紹介された戦績は `reported_battles`（戦数）と `reported_wins`（勝数）に、元のページは `url` に入ります。無ければ空です。

ゲームは戦闘の日時を「20時間前」のようにしか表示せず、同じ相手との戦闘が続けて並ぶこともあります。
そこで Rio は、12 人のダメージを `a1` から `dsp2` の順に `-` でつないだ文字列を戦闘の指紋とし、
指紋が同じなら同じ戦闘として扱います。
ダメージは勝敗をほとんど表さないので（回復や被弾は数えず、召喚物や回復した相手を攻撃すると増えます）、
指紋のほかには使いません。

SQLite を読める道具（`sqlite3` コマンドなど）で、自分で引き出せます。
たとえば、プレイヤー 2 番が防衛したときの編成は次のように出します。

```sh
sqlite3 "%APPDATA%\io.github.miyabisun.bluearchive-rio\rio.db" "SELECT seen_at, attacker_won, d1, d2, d3, d4, dsp1, dsp2 FROM battles WHERE defender = 2"
```

## 読めないとき

Rio は、戦闘履歴のどこか 1 か所でも確実に読めなければ、その戦闘を登録しません。間違った記録を残さないためです。
読めない間、右上の表示は「戦闘履歴を読み取り中」のまま変わりません。

- ウィンドウの横幅が 1500 ピクセルより狭いと読みません。
- 幅によっては数字を読み切れないことがあります。ウィンドウの大きさを少し変えると読めます。
- 実装されたばかりの生徒は、Rio が持つ生徒の一覧にまだいません。下の「生徒の一覧の更新」で取り込みます。
- 生徒が 6 人そろっていない編成は、まだ読めません。
- 戦闘履歴の一覧で読めない行は、上の「戦闘履歴の一覧」にあります。
- 「編成」の画面のうち、「SPECIAL」のタブを開いた状態と、編成に空きがある状態は、まだ実際の画面で確かめていません。

## 開発

[Rust](https://www.rust-lang.org/ja/tools/install) を入れて `cargo build --release` を実行すると、
`target\release\bluearchive-rio.exe` ができます。使う Rust の版は `rust-toolchain.toml` にあり、rustup が自動で入れます。
検査は `sh tools/checks.sh` でまとめて走ります。中身は次の 3 つと、下の「Rust の版の追従」のスクリプトのテストです。

```sh
cargo fmt --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked
```

ウィンドウは [GPUI](https://www.gpui.rs/) で描きます。画面の規則は [DESIGN.md](DESIGN.md) にあります。

main へ push する前に同じ検査を走らせるには、クローンごとに 1 回 `git config core.hooksPath .githooks` を実行します。
配布する実行ファイルは、バージョンのタグが付いたコミットから GitHub Actions（`.github/workflows/release.yml`）が作ります。

読み取りのテストは、ゲームの画面の画像を `tests/fixtures` から読みます。
対象は `tests` の `history.rs`・`list.rs`・`opponent.rs`・`formation.rs` です。
画面にはプレイヤーの名前が写るので、この画像はリポジトリに含めていません。画像が無いと、読み取りのテストは失敗します。

- 生徒の一覧の更新: `powershell -File tools/schaledb/update.ps1` を実行します。
  [SchaleDB](https://schaledb.com/) から日本版の生徒の一覧とアイコンを `data/schaledb` に取り込みます。
- 読み取りの手本の作り直し: `cargo run --example make_refs` を実行します。
  `tests/fixtures` の画面から、読み取りの手本を `data/` に切り出します。
  手本は、3 つの画面の題字・攻撃と防衛の絵・ダメージの数字・匿名の「？」の絵・一覧の時刻の文字です。
  [Noto Sans JP](https://github.com/notofonts/noto-cjk/tree/main/Sans/SubsetOTF/JP) の `NotoSansJP-Bold.otf` を置いたフォルダを
  引数に付けると、ゲームの上に出す文字の絵（`data/words`）も描き直します。

### Rust の版の追従

Rust の版は固定したままにしません。GitHub Actions の実行環境が持つ版（GitHub が採用した最新の安定版）へ追従します。
版を書く場所は `rust-toolchain.toml` だけです。

| すること | コマンド | 動き |
| --- | --- | --- |
| 見張る | `bash tools/rust/follow.sh` | このリポジトリの版と、GitHub の実行環境の版を表示する。遅れていれば終了コード 10 |
| 追従する | `bash tools/rust/follow.sh --apply` | `rust-toolchain.toml` を新しい版に書き換え、検査をすべて通してからコミットする。検査が落ちたら何も変えない |
| 直してから追従する | `bash tools/rust/follow.sh --mend` | 新しい版を書き込むだけで、コミットしない。新しい版の検査（clippy の新しい指摘など）に合わせてコードを直した後で `--apply` すると、直しと版を 1 つのコミットにする |

- push の前の門（`.githooks/pre-push`）が毎回見張ります。遅れていると、その場で追従のコミットを作って push を止めます。
  もう一度 push すると、追従のコミットも一緒に送られます。
- GitHub の版は、実行環境に入っているソフトの一覧（[actions/runner-images](https://github.com/actions/runner-images)）から読みます。
  どの一覧かは、最後のリリースの実行の記録が教えます。`gh` が無いときと通信できないときは、見張らずに通します。
- 新しい版ではまだ検査を通せないときは、`FOLLOW_RUST=off` を付けて push すると、見張りを飛ばせます。
- 追従のコミット（`chore: follow Rust …`）を push すると、GitHub Actions はビルドだけを行い、公開はしません。
  新しい版でのビルドのキャッシュがここでできるので、次のリリースが待たされません。
